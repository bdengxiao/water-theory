# 制作过程与复盘

这份记录依据项目对话与已观察到的工具结果整理，时间范围为 2026 年 10 月 14—15 日。它是便于公开阅读的项目复盘，不是原始聊天、逐字指令或平台安全日志。

## 1. 确定互动场景

用户提供了域名管理截图和视觉参考，希望做一个带人物、马赛克、大量水瓶、空中句子和互动效果的网页。项目围绕蓝色水世界建立首屏，而不是先做传统的多页导航网站。

人物和水瓶采用 AI 生成的虚构视觉资产。整张脸打马赛克，衣服没有品牌商标，瓶身最终使用用户选定的“大水”。

## 2. 从首屏扩展成可反复玩的网页

实现点击收集句子、拖动水瓶、长按或空格键涨水、暂停、重置和可选声音。手机触屏也有对应操作。

用户要求更多梗，随后加入文案类型切换、收藏展示。视觉上继续调整瓶子质感、文字层次、玻璃效果、间距和手机布局。

## 3. 加入饮水记录与思维测试

后续需求增加了每日喝水记录，以及“有没有大水理论思维”的娱乐测试。

饮水记录支持快捷加量、自定义毫升数、补记日期、撤销与删除、可选个人目标、最近 7 天展示，以北京时间分日。测试使用 6 道原创题目，支持返回、保留选择、查看结果和复制结果。

这些数据只保存在当前浏览器，没有做登录、跨设备同步或云端个人数据存储。

## 4. 区分公开原话与原创梗

用户指出“不能只有原创，也要有他自己说的话”。随后依据公开采访与报道保留了 4 条短句节选，标注语境、日期和链接，另保留 24 条原创梗句。

原话与原创在数据和界面上分别标识。香蕉相关句子采用报道所载中文译文，没有宣称核验了原始中文发言。详情见 [SOURCES.md](../SOURCES.md)。

## 5. 初次发布与域名接入

网站先通过 Sites 托管发布，再配置自有域名。站点最初存在访问权限门槛，之后按用户要求改成公开，并加入页面标题、描述、canonical、站点地图和 robots 文件。

这只能说明访问权限和基础发现信息已配置，不能保证任何网络都能访问，也不能保证搜索引擎收录。

## 6. 手机访问失败，重新选择托管

用户的手机 Wi-Fi 和移动网络遇到 Cloudflare 拦截页，页面写明无法访问原托管平台的域名。截图中的请求编号是诊断线索，但没有给出具体触发规则。

我们没有把它归因于用户密码、网页前端代码，或在缺乏日志时认定为某一地区统一被封。当前站点管理工具没有暴露平台防火墙放行入口，因此改为检查用户已有的腾讯云托管服务。

账户已有 EdgeOne Makers 免费静态网页托管。网页被打成只有静态文件的部署包，用户在浏览器里选中文件，随后部署成功。

## 7. 费用、节点与备案的取舍

讨论中一度检查了包含中国大陆节点的全球配置及备案流程，也查看过一款付费轻量服务器报价。用户明确不接受这项成本，最终没有购买服务器，继续走免费托管方案。

这里必须区分三个概念：

- 自有域名与平台临时域名不是同一条访问路径，平台临时域名可能有地区或有效期限制。
- “境外节点”描述服务节点分布，本身不能推导为大陆用户一定无法访问自有域名。
- 使用包含中国大陆节点的配置，按该平台当时说明要求域名完成 ICP 备案。

讨论中的表述曾把这些概念讲混，后续已纠正。最终采用的是不含大陆节点的免费方案；大陆实际访问能力需要手机实测，不靠选项名字判断。

## 8. 域名切换与免费 HTTPS

验证域名归属后，旧平台的两条 A 记录被停用保留，新增指向新平台的 CNAME，公开 DNS 查询确认了切换。记录可恢复，没有删除原网站源码。

新平台当时的直接免费证书入口不可用，于是通过腾讯云 SSL 控制台另行申请免费证书。采用手动 TXT 验证，公开 DNS 能查到验证值，之后证书签发并部署到网站。本人扫码、服务授权等步骤由用户完成。

最终观察到：电脑浏览器能显示正式网页；未设置请求代理的 HTTPS 检查和使用现有代理的检查都返回 200，响应来自新托管平台。未更改操作系统或代理软件的网络配置。

## 9. 什么已经确认，什么仍需验证

| 事项 | 制作时的证据与边界 |
| --- | --- |
| 静态站点部署 | 腾讯云控制台显示成功 |
| 域名解析 | 控制台记录与公开 DNS 查询相符 |
| HTTPS | 免费证书已签发、已部署，HTTPS 请求成功 |
| 电脑浏览器 | 已看到完整页面 |
| 所有手机、运营商、国家和地区 | 没有完成全球覆盖验证，不能保证 |
| 搜索引擎收录 | 仅有基础页面信息与 sitemap，未确认收录 |
| 免费证书长期有效 | 有到期时间，需要维护与续签部署 |

不上传控制台截图、扫码页面、凭证、证书私钥、云服务内部标识、完整聊天记录或浏览器个人记录。原部署仓库的 Git 历史和平台绑定文件也不进入这个新公开仓库。
